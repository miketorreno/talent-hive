# Postgres data model

Talent Hive stores its canonical data in PostgreSQL (RDS 16), the schema defined idempotently in `packages/shared/shared/postgres/schema.sql` and applied via `apply_schema()`. The relational model is a projection of the `domain` entities behind the existing repository seams: `users` (sole identity keyed by Telegram ID) with a `user_roles` join table since a user may hold both `employer` and `job_seeker` roles; `companies` with `company_recruiters` for owner/recruiter membership and a `UNIQUE(owner_id)` mirroring the one-company-per-owner rule; `jobs` keyed to a company with a `job_status` enum; `seeker_profiles` (one per seeker, `PK(seeker_id)`, skills/experience as `jsonb`); `applications` with an `application_status` enum and a `UNIQUE(job_id, seeker_id)` that dedupes a seeker applying to a job; and `artifacts` (cover letters, resumes, job descriptions) tagged by `artifact_type`/`artifact_origin` with a partial unique index `one_resume_per_owner_idx` so a user holds at most one resume while any number of other artifacts.

The repository shells live in `packages/shared/shared/postgres/repositories.py` as `PostgresStore`-provided repos (`.users`, `.companies`, `.jobs`, `.profiles`, `.applications`, `.artifacts`). Each implements the same abstract repository interface as its Redis counterpart (from `shared.store`), so the two sets are swappable behind the `Store`/`PostgresStore` seam, and — shaped to mirror the Redis implementations — surfaces the same domain rules at the seam: notably `PostgresCompanyRepository.save()` re-checks one-company-per-owner and raises `CompanyError` per ADR 0002, while application dedupe and one-resume live as database constraints. Because dependent rows carry foreign keys to `users`, `save()` lazily upserts the referenced Telegram user via `_ensure_user()` so the repos stay self-contained thin shells. Behavioral tests stay in `domain`; the Postgres integration tests in `packages/shared/tests/test_postgres_stores.py` run against a real database (skipped when unreachable, configurable via `TH_TEST_DATABASE_URL`).
